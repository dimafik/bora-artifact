The fairness-based leads-to argument is FULLY mechanised:

NO fact remains an AXIOM.  The two action-enabledness statements -- "a pending

CORRECTION (this supersedes the earlier note in this file).  ExpandENABLED IS
operational in this tlapm 1.5.0 install.  The earlier diagnosis rested on a single
probe, ENABLED <<x' = x+1>>_vars, which bundles two obligations -- expanding ENABLED
and discharging the stuttering-exclusion conjunct vars' # vars -- into one.  Asked
separately, both succeed.  Re-tested properly:
  positive control (EnTest.tla)  : ENABLED Bump and ENABLED <<Bump>>_vars, 5/5 proved;
  negative control (EnFalse.tla) : an action with x' = x+1 /\ x' = x, and one with an
                                   unsatisfiable guard, 2/4 correctly REFUSED.
The tactic therefore discriminates true from false and is not inert.

Consequence: ElectEnabled is now a PROVED THEOREM in Liveness.tla (PICK the pending
candidate, ENABLED <<BecomeLeader(i)>>_vars by ExpandENABLED, then lift over the
existential in ElectStep).

CampEnabled is now proved as well, so Liveness.tla has NO axioms.  Reaching it
took ruling out three wrong explanations for why the lift over CampStep's
existential failed while the same lift succeeded for ElectStep:
  - context clutter          ruled out (EnCamp.tla V1,V2: minimal context, still fails)
  - mixed arithmetic         ruled out (EnCamp.tla V4: disequality and arithmetic
                             supplied as separate facts, still fails)
  - the action itself        ruled out (EnBisect.tla: the CONTROL, BecomeLeader,
                             fails too under a one-line BY, with or without full
                             TypeOK) -- this was the turning point, since that
                             action's lift demonstrably works inside Liveness.tla
The actual rule is about PROOF SHAPE: PICK the witness out of an EXISTENTIAL
PREDICATE, prove ENABLED for that fixed instance, state the action implication, then
close with every ENABLED fact-set at once.  ElectEnabled already had that shape
because PendingCand is an existential.  The failing CampEnabled derived concrete
facts about orderer 1 and picked from those, so the witness was never tied to the
goal's existential the way the ENABLED rules need.  Introducing
  SomeFollower == \E i \in Orderers : state[i] = "follower" /\ currentTerm[i] < MaxTerm
and picking from it closes it.  EnPair.tla shows BOTH actions closing under the
identical recipe (36/36), which is the confirmation that the action was never the
difference.  Both facts remain independently model-checked in Enabledness.tla.

Probabilistic rate: the randomized-timeout RATE (w.p.1, geometric decay) is a
PROBABILISTIC property, not expressible in (non-probabilistic) TLA+/TLAPS.  It is
verified SEPARATELY in PRISM (see ../prism/PRISM_RESULT.txt): a DTMC of the
randomized-timeout election within the eligible set gives P>=1[F leader]=true (w.p.1)
and a geometric no-leader decay (1-q)^k, expected rounds 1/q (2.7/4.0/6.4 for
|E_t|=3/4/5 in the adversarial two-slot window).

KEY TLAPS IDIOMS that made closure possible in this install (Zenon + SMT + Isabelle all
work; the earlier "blocked" diagnosis was a proof-STRUCTURING issue, not a backend gap):
  1. A step/lemma ASSUME keeps only NEW declarations; ANY predicate hypothesis (Inv,
     Q, P, Campaign(j), even a raw state[i]="x") is dropped.  Fix: assume only NEW,
     keep every predicate (the invariant AND the action) in the GOAL ANTECEDENT, e.g.
     LEMMA L == ASSUME NEW j PROVE (Inv /\ Campaign(j)) => Goal.
  2. No single backend does everything: SMT for interval/arith (x \in 0..N, x+1 \in
     0..M) and EXCEPT-with-domain; Zenon for function-application/constructor/set
     assembly; Isabelle "Auto" for Append/Len of Seq; SequenceTheorems `ElementOfSeq'
     for s[k] \in S typing.  N \in Nat / MaxTerm \in Nat must be in the assumptions for
     SMT to reason about the intervals.
  3. ENABLED expansion works (ExpandENABLED).  To lift it over an existential,
     PICK the witness FROM AN EXISTENTIAL PREDICATE (not from concrete facts about a
     particular index), prove ENABLED for that instance, state the action
     implication, and close with ENABLEDrules + ENABLEDaxioms + ENABLEDrewrites +
     ExpandENABLED together.  A one-line BY ExpandENABLED does not do it.

=== Per-voter (decentralised) model: BORA_pv.tla / BORA_pv_proof.tla / BORA_pv_excl.tla ===
The deployment gives every orderer its own sidecar, so the blacklist is per-voter and
only eventually consistent.  These modules replace the global set by
    blacklist \in [Orderers -> SUBSET Orderers]
BoundedIntelligence hands each voter an arbitrary set on every step; NOTHING in the
spec forces the views to agree.  The tick guard reads a node's OWN view; the vote
guard reads a QUORUM of views.

  Safety refinement (BORA_pv_proof.tla):
      tlapm --cleanfp -> "All 48 obligations proved."  EXIT=0.
    Same theorem as the global model (Spec => Vanilla!Spec).  No new lemma was
    needed: both guards only ADD preconditions to actions vanilla Raft already
    permits, and removing behaviours cannot break a refinement.  Safety therefore
    holds however far the per-voter views diverge -- no agreement premise enters.

  Exclusion (BORA_pv_excl.tla):
      tlapm --cleanfp -> "All 64 obligations proved."  EXIT=0.
    THEOREM Exclusion_PV_Thm ==
      Spec => [][ (QuorumHolds(i) /\ ~failOpen) => ~Acquires(i) ]_vars
    This is Proposition 7 of the paper, verbatim.  NON-VACUITY was checked by
    mutation: a duplicate module with ONLY the vote-grant guard deleted from
    BecomeLeader fails 1 of the 64 obligations, at <3>2 (j # i) -- exactly the step
    that uses the guard.  The proof therefore depends on the guard rather than
    following from unrelated structure.  The mutated module was removed after the
    check.

  NOT proved, and not provable in any protocol model: whether an honest quorum
  actually agrees inside a given election window.  That is a deployment timing
  property; the paper measures it on the testbed instead.
